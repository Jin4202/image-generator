# T13 — 늦은 유료 제출 방지

선행: T06/T07/T12. 우선순위 P1.

## 소유 파일
src/application/ports.ts, src/application/services/runs.ts, src/infrastructure/models/fal-contract.ts, src/infrastructure/models/fal.ts, src/infrastructure/models/mock.ts, tests/acceptance/T13.cases.test.ts(신규). 계약 변경에 따른 기존 adapter 테스트 double 수정은 signature 적응만 허용.

## 필수 계약/참조
contracts.md의 runs/fal, ADR 004, follow-up-plan.md. external()의 Promise.race는 upload를 취소하지 않으므로 timeout→unknown→abandon 이후에도 POST가 시작될 수 있다.

## 구현 순서
1. ModelAdapter.submit과 FalTransport에 전달할 실행 context를 계약화한다: AbortSignal과 POST 직전 동기 권한 확인 callback. callback은 application이 제공하고 infrastructure가 DB를 직접 참조하지 않는다.
2. runs에서 한 제출 시도의 30초 deadline과 lease 상실을 같은 취소 신호로 연결한다. 권한 검사는 현재 owner의 유효 lease와 해당 run의 submitting/revision을 확인한다. 취소되면 새 upload와 POST를 시작하지 않는다.
3. 모든 await 뒤 취소 확인, 유료 POST 직전 재검사. 마지막 권한 검사와 fetch 호출 사이에 await를 넣지 않는다. SDK upload를 물리적으로 중단할 수 없어도 완료 후 POST는 반드시 막는다. transport는 signal을 HTTP 요청에 전달한다.
4. 늦은 응답의 DB 기록은 기존 lease/CAS 규칙을 유지한다. 이미 보낸 요청의 abort는 provider 취소/환급을 보장하지 않는다. timeout은 기존 unknown 처리와 자동 재제출 금지를 유지한다.
5. 수동 제어 가능한 upload Promise와 fake timer로 회귀 테스트 작성.

## 인수 기준
- upload 대기 중 timeout→unknown→사용자 abandon→upload 완료: 유료 POST 0회, run failed 유지, requestId null.
- lease 상실/다른 worker 인수 후 upload 완료: POST 0회.
- 정상 제출 POST 1회. 이미 POST가 시작된 뒤 timeout/응답 유실: unknown, 재제출 0회.
- 종료된 시도의 timer/heartbeat 정리, 늦은 reject의 unhandled rejection 없음.
