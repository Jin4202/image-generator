작성: 2026-10-26. 상태: **T13–T18 구현 완료(2026-10-26)** — 증거는 [status.md](status.md). 아래 본문은 계획 당시 기준이다.

T01–T12 완료 후 프로젝트 검토에서 발견한 세 결함과 사용자 요청(API 키 입력, 프로젝트 편집/삭제, 에셋 표기)을 포함한다. 이번 변경은 문서만 추가한다. 기존 완료 증거를 무효화하지 않지만, 기존 테스트 통과가 아래 결함의 부재를 보장하지는 않는다.

## 계약 확정과 구현의 구분

각 문서의 정책은 후속 설계 기준이다. 현재 코드에 이미 적용된 계약으로 오해하지 않는다. T13/T16/T17은 포트·공개 DTO/API 변경이 필요하므로 **해당 작업의 첫 산출물은 계약 변경과 회귀 테스트 명세**다. 아래 문서에 명시한 변경 범위 안에서 docs/contracts.md, docs/architecture.md, 관련 ADR과 타입을 함께 갱신한다. 미명시 상태 전이나 정책은 구현자가 추정하지 않고 docs/blockers.md에 기록한다.

기존 index.json은 현재 실행 가능한 T01–T12의 파일/테스트 inventory다(구현 후: T13–T18도 등록, 기존 파일 이관은 `inheritedFiles`로 표시하고 `check-handoff`가 같은 파일을 이어받는 작업 사이의 의존 경로를 검사한다). 아직 존재하지 않는 후속 테스트를 억지로 등록하거나 소유권 검사를 약화하지 않는다. 후속 작업을 구현할 때 기존 파일 소유권 이관을 지원하는 inventory 구조와 검사를 먼저 정합적으로 갱신하고 등록한다. 그 전까지 후속 진행의 기준은 이 문서와 status.md다.

## 공통 완료 조건

- 해당 작업의 정상·실패·경계 회귀 테스트 작성 후 통과. 아래 신규 테스트 경로는 예정 파일이며 현재 존재/통과를 의미하지 않는다.
- npm run verify, npm run test:acceptance, npm run test:e2e, npm run test:e2e:acceptance 통과.
- 테스트는 임시 APP_DATA_DIR와 mock/주입 transport 사용. 실제 fal 호출과 과금 없음.
- 기존 assertion 삭제·약화 금지. 문구 변경은 같은 행동을 검증하는 locator/기대 문구만 변경.
- status.md에 변경 파일, 계약 변경, 명령/결과, 미해결 항목 기록. 실패/보류는 완료로 기록하지 않는다.

다음 세션 지시 예: “AGENTS.md, docs/tasks/follow-up-plan.md, docs/tasks/T13.md를 읽고 T13만 수행해줘. 먼저 계약과 회귀 테스트를 구체화하고, 명시된 범위에서 구현한 뒤 검증 결과를 기록해줘.”
