## 구현 순서

1. config→repo/blob/imageInspector(`createSharpImageInspector`)/imageCompositor(`createSharpImageCompositor`)/adapters를 조립하고 server singleton/worker factory 분리.
2. worker CLI graceful shutdown과 readiness 연결; migration 누락은 명시적 오류. T06의 `runWorker(deps, owner, signal)`는 abort 후 진행 중 tick을 마치고 lease를 해제한 뒤 resolve한다. SIGINT/SIGTERM → AbortController.abort와, resolve 후 `repo.close()`는 `src/worker/main.ts`가 담당한다.
3. 임시 production501과 초기 화면 M0/미구현 assertion을 실제 동작/준비 상태 assertion으로 교체한다. root 화면을 제품 진입/프로젝트 링크로 바꾸되 mock demo의 명시적 표시는 유지한다.
4. scripts/e2e-stack.ts에서 mkdtemp APP_DATA_DIR, migration, worker+Next child process를 순서대로 띄운다. Playwright webServer command가 이 스크립트를 실행하도록 연결한다. T02에서 next dev on-demand compile race 때문에 임시로 넣은 `workers: 1`(docs/blockers.md)은 production stack 전환 후 재검토한다. 종료 신호에서 두 child를 종료하고 DB를 정리한다. 기본 DB를 테스트에 사용하지 않는다.
5. mock 기반 full-flow 및 별도 프로세스 restart/unknown resume 테스트를 추가한다.
6. 기본/acceptance/e2e 전부 실행하고 완료 증거 기록.

## 인수 기준

prod routes 구현; source 수정 없이 전체 mock 흐름; 서버/worker 재시작 후 lineage 복원; key client bundle/export 미포함; 모든 task suite pass.

현재 acceptance suite는 최소 실행 명세다. 위 기준의 미포함 정상/실패/경계 case를 추가하여 완료해야 한다. 기존 테스트를 삭제/약화하거나 반환형을 바꾸지 않는다.

## 검증 명령

```sh
npm run test:acceptance -- tests/acceptance/T12.test.ts
npm run verify
npm run test:e2e
```

추가: `npm run test:acceptance`, `npm run test:e2e:acceptance`. 기존 T12 API 테스트는 임시 APP_DATA_DIR를 자동 생성/마이그레이션/정리한다. 새 테스트도 같은 원칙을 따른다. 실제 fal 호출 없이 mock으로 수행한다.
