## 구현 순서

1. 각 페이지를 HTTP client로 연결하고 query selection/loading/error/empty 상태 구현.
2. preview 상세/참조 순서/경고/비용 동의를 UI로 표시.
3. 생성/후보 비교/평가/child/효과/다운로드/이력 흐름 연결.
4. API fixture를 page.route로 대체해 브라우저 tests 작성; 실제 wiring은 T12 이후 전체 E2E.

## 인수 기준

장면 미선택 생성 disabled; unknown cost 명시 동의 전 submit0; reload 선택 복원; 501을 성공처럼 표시하지 않음.

현재 acceptance suite는 최소 실행 명세다. 위 기준의 미포함 정상/실패/경계 case를 추가하여 완료해야 한다. 기존 테스트를 삭제/약화하거나 반환형을 바꾸지 않는다.
