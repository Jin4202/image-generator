# T14 — 저장 스케치 이어서 편집

선행: T04/T10/T12. 우선순위 P2.

## 소유 파일
src/components/canvas/scene-canvas.tsx, src/app/scenes/page.tsx, tests/e2e-acceptance/T14.sketch.spec.ts(신규).

## 필수 계약/참조
contracts.md의 scenes, 기존 T04/T10 canvas 테스트. 현재 strokes=[]로 열려 기존 PNG가 새 export에서 사라진다.

## 구현 순서
1. 편집 대상 sketch 참조의 저장 PNG를 canvas의 편집 바탕으로 읽는다. 여러 sketch 참조가 있으면 사용자가 편집 대상을 선택하고 선택한 참조 하나만 갱신한다. 새 스케치 생성은 명시적 별도 동작.
2. 바탕과 새 stroke를 같은 raster 편집 대상으로 합성한다. 지우개는 기존 바탕과 새 stroke 모두에 작용하며 최종 PNG의 지운 영역은 기존 흰 배경 정책을 따른다. boxes는 스케치 PNG에 굽지 않는다.
3. 로딩/실패 중 export·저장 차단. 장면 또는 편집 참조 전환 시 이전 이미지의 늦은 load 결과를 무시한다. 원본 이미지 전체를 현재 canvas 크기로 매핑한다.
4. 새 PNG 업로드 성공 후 scene CAS 저장. 실패하면 기존 sketch 참조 보존. 원본 blob 불변. 과거 stroke 단위 undo 복원은 제공하지 않는다.

## 인수 기준
새로고침 후 기존 그림 표시; 새 선 추가→저장→재조회에서 기존·새 픽셀 모두 유지; 기존 선 지우기 반영; 이미지 로드 실패 시 빈 그림 덮어쓰기 없음; CAS 충돌 시 기존 서버 scene 보존; 다른 참조/장면으로 전환 시 그림 누출 없음. PNG 픽셀을 검사하여 링크 표시만으로 통과하지 않게 한다.
