## 구현 순서

1. submit replay/hash/expiry/budget/active cap을 하나의 transaction으로 구현.
2. tickWorker lease/heartbeat/상태별 단일 step을 구현, 제출 intent를 먼저 commit.
3. provider unknown/lease loss/restart recovery, poll transient, download 실패 재시도를 구분.
4. candidate/output DB commit 원자성/unique(run,index) 검증.
5. runWorker loop/signal/lease release를 구현한다.

## 인수 기준

같은 intent의 submit 횟수1; ambiguous submit 반복tick에서도 재제출0; restart poll 복구; failed download는 생성 재요청0; known/unknown budget 경계.

현재 acceptance suite는 최소 실행 명세다. 위 기준의 미포함 정상/실패/경계 case를 추가하여 완료해야 한다. 기존 테스트를 삭제/약화하거나 반환형을 바꾸지 않는다.
